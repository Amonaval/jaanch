# M13.1 — Assessment Quality Recovery + Block UX v2

Effort: **HIGH**
Status: **ENGINEERING IMPLEMENTED — OWNER TRUST-GATE RETEST REQUIRED**
Origin: first hands-on owner review after M13

## Why this mission exists
The first real product test showed that Jaanch had an auditable engine but an intake experience too shallow, constrained and question-by-question to support credible assessment quality.

This mission is corrective, not cosmetic. **Input quality determines output quality.**

## Engineering implementation

### Block-based flow
Primary sections:
1. About you & measurements
2. Health history & medicines
3. Current health & symptoms
4. Lifestyle
5. Known tests & measurements

Adaptive history, safety, sleep and other follow-up blocks are inserted only when relevant. Safety follow-up is inserted immediately after Current health when activated.

### Navigation integrity
- stable block IDs;
- visited Back/Forward state is independent of dynamic eligibility;
- Back → Forward returns to the same visited block while the plan is unchanged;
- if an earlier edit changes the plan, stale Forward history is discarded;
- newly activated safety/adaptive blocks therefore cannot be skipped by old history;
- direct section navigation is available for review/edit;
- custom/manual answers are not silently deleted by replanning.

### Richer capture
- broader diagnosed-condition catalogue + manual Other;
- named medicines with category/purpose;
- named supplements;
- broader concern/symptom catalogue + manual Other + detail text;
- broader family history + manual Other;
- walking days/minutes/steps/pace;
- structured activity type/days/minutes/intensity;
- human-friendly height/waist/weight units with canonical metric storage;
- additional health context.

### Known evidence
Currently interpreted normalized lab pathway remains limited to:
- HbA1c;
- Vitamin B12.

Broader structured capture now includes:
- Vitamin D (25-OH);
- fasting/random glucose;
- total cholesterol;
- LDL;
- HDL;
- triglycerides;
- hemoglobin;
- ferritin;
- TSH;
- blood pressure;
- Other/manual measurement.

Unsupported markers are retained as `recorded_unassessed`; they do not alter deterministic findings until a sourced/applicable rule exists.

### Persistence / internal packet
- longitudinal snapshots retain `capturedContext`;
- internal HAP can retain richer captured context;
- external AI packet policy remains separately minimized/opt-in and is not automatically widened by this mission.

### Consumer UX
- grouped mobile-first cards/sections;
- section progress rather than question count;
- clickable section navigation;
- chips + manual entry patterns;
- clearer measurement units;
- improved Health Map hierarchy;
- `Recorded, not yet assessed` surfaced separately from findings;
- technical provenance remains secondary/detail content.

## Automated regression scope
The M13.1 verification suite covers:
- unit conversions;
- walking contributes to the derived activity summary;
- named medicine/manual condition/Vitamin-D context preservation;
- capture catalogue breadth;
- exact Back → Forward adaptive preservation bug;
- stale adaptive forward history removal after plan-changing edits;
- newly activated safety block interrupts next navigation;
- custom context survives longitudinal serialization;
- richer context is retained in internal HAP.

## Owner trust-gate scenarios
Engineering completion is not product validation. Retest:
1. healthy adult;
2. vegetarian with known low B12 + low Vitamin D;
3. cholesterol + blood-pressure medicine;
4. daily walker with little formal exercise;
5. unlisted diagnosis + unlisted concern;

## Exit criterion
M13.1 becomes **PRODUCT VALIDATED** only when hands-on retest confirms:

Any trust-gate defect found in retest stays inside M13.1 and is fixed before M13.2.
