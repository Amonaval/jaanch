# M13.2 — Result Quality + Health Map Consumer UX v3

Effort: **HIGH**
Status: **ENGINEERING IMPLEMENTED — OWNER RESULT-UX RETEST REQUIRED**
Depends on: M13.1 intake trust gate / block UX

## Why this mission exists
M13.1 improved what Jaanch can faithfully capture. The result experience still exposed engine-shaped output: findings, investigations, recommendation cards, safety data and provenance were individually correct but the user had to assemble the meaning.

M13.2 turns those artifacts into one shared consumer narrative without changing the underlying clinical rule set.

## Consumer questions the Health Map must answer
1. **What matters now?**
2. **What can I safely do next?**
3. **What does the current evidence support?**
4. **What is still uncertain or worth measuring?**
5. **What changed since my last saved check-in?**

Technical provenance, safety decisions, source IDs and HAP remain available as secondary detail rather than the default reading order.

## Shared result model
Added `buildConsumerResultViewModel` in the shared core.

It combines:
- deterministic assessment output;
- Health Map presentation model;
- recommendation plan;
- latest saved longitudinal snapshot;
- current preview snapshot;
- count of preserved-but-uninterpreted context.

The shared model drives both web and mobile so platform UIs cannot silently disagree on result ordering or wording.

## Hero states
The result hero has four bounded states:
- `urgent` — configured red flag is active;
- `attention` — actionable screening signal exists;
- `needs_evidence` — no urgent signal, but meaningful uncertainty remains;
- `quiet` — no high-priority issue from evidence Jaanch can currently interpret.

The quiet state deliberately does **not** say the user is healthy or normal.

## Evidence completeness rule
Evidence completeness remains visible but now explicitly states:
> Completeness measures available evidence, not overall health.

It must never be styled or described as a health score.

## Default result hierarchy
### 1. Hero
- bounded status headline;
- short explanation;
- evidence completeness context;
- one best-next-step sentence.

### 2. What matters now
Up to four urgent / screening / evidence-priority items.

### 3. What you can do
Top safe recommendations with:
- priority;
- disposition;
- rationale;
- short concrete steps.

Urgent red-flag state suppresses routine recommendation cards through the existing recommendation engine.

### 4. What the evidence supports
Consumer summary of interpreted findings, with confidence/evidence level retained but secondary.

### 5. What is still uncertain
Combines unresolved finding evidence gaps with the minimal useful investigation set.

### 6. Since your last saved check-in
Current unsaved assessment is compared with the latest saved snapshot so the user can see meaningful change before deciding to save today.

The change summary includes:
- improved/worsened/new/resolved findings;
- eligible HbA1c/B12 changes;
- evidence-completeness delta.

### 7. Recorded, not yet interpreted
Custom conditions, medicines, supplements, broader labs and free-text health context remain visible as retained facts without being promoted into unsupported conclusions.

### 8. Technical details
Clinical governance, underlying findings and HAP stay available behind detail disclosure on web. Mobile keeps the default surface consumer-first.

## Safety / honesty boundaries
- no overall health score;
- no `you are healthy` conclusion;
- no conversion of uncertainty into diagnosis;
- no new clinical thresholds in this mission;
- no widening of autonomous treatment authority;
- urgent safety state still overrides routine planning;
- recorded/unassessed context remains non-inferential.

## Automated regression scope
Presentation verification now covers:
- attention-oriented hero for an actionable profile;
- concrete best-next-action availability;
- separation of supported evidence vs uncertainty;
- explicit `not overall health` completeness wording;
- urgent result suppressing routine actions;
- pregnancy safety restrictions preserved;
- change-since-last-check-in summary;
- deterministic repeatability of the consumer result model.

## Owner retest scenarios
1. healthy/low-risk adult — verify wording does not over-reassure;
2. metabolic-risk profile — verify priorities and actions are immediately understandable;
3. vegetarian + B12 uncertainty — verify evidence gap and action are not duplicated/confusing;
4. known low B12 result — verify measured evidence dominates questionnaire suspicion;
5. broader recorded values such as Vitamin D/lipids — verify they remain visible as recorded/unassessed;
6. urgent chest-pain path — verify urgent message visually dominates and routine actions disappear;
7. save one check-in, change activity/waist/lab evidence, rerun — verify `Since your last saved check-in` is useful;
8. no meaningful change — verify the app says so plainly rather than inventing progress;
9. compare web and mobile — verify same result meaning/order even if layout differs.

## Exit criterion
M13.2 becomes **PRODUCT VALIDATED** when the owner can answer, without opening technical details:
> What matters, what should I do, what is still unknown, and what changed?

Any result-clarity defect found during this retest remains in M13.2 before M13.3 begins.
