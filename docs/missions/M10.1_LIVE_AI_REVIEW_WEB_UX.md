# M10.1 — Live AI Review + Web UX

Status: **ENGINEERING IMPLEMENTED — LIVE REAL-MODEL UTILITY GATE / OWNER REVIEW REQUIRED**  
Effort: **High**

## Objective

Turn the already-engineered M10 AI harness into a real, visible web workflow without turning AI into Jaanch's source of truth.

M10.1 is deliberately a second-pass review experience:

```text
saved deterministic check-in
        ↓
internal HAP
        ↓
explicit one-run consent
        ↓
privacy-minimized JAANCH-AI-REVIEW-1.0 packet
        ↓
same-origin server endpoint
        ↓
server-only OpenAI Responses provider
        ↓
strict structured output
        ↓
Jaanch schema + safety invariant validation
        ↓
validated advisory UI only
```

The deterministic assessment, safety gates, applicability decisions, evidence eligibility and recommendations are never mutated by AI output.

## What changed

### 1. Packet-only network boundary

New shared-core helper:

```text
packages/core/src/aiReviewRuntime.ts
```

`runAIReviewPacket(...)` allows the server runtime to review an already privacy-minimized packet instead of requiring the full internal HAP.

For the web workflow this means:
- the saved check-in/HAP stays in the browser;
- the browser creates `JAANCH-AI-REVIEW-1.0` only after explicit consent;
- raw questionnaire answers are omitted before the POST request;
- only the minimized packet crosses the browser/server boundary.

### 2. Same-origin server endpoint

New runtime module:

```text
packages/ai-runtime/src/httpHandler.ts
```

The handler:
- accepts POST only;
- accepts only a `JAANCH-AI-REVIEW-1.0` packet body;
- requires packet consent to be true;
- rejects arbitrary/raw-answer request bodies;
- caps request bodies at 256 KiB by default;
- never logs the health payload;
- returns `Cache-Control: no-store`;
- calls the existing server-only OpenAI Responses provider;
- returns the common `AIReviewRunResult` contract.

Provider credentials never enter browser code.

### 3. Vite web integration

New:

```text
apps/web/vite.config.ts
```

During local Vite dev/preview, `/api/ai-review` is mounted server-side using `@jaanch/ai-runtime`.

Configuration comes from the repository-root `.env.local`:

```text
JAANCH_AI_LIVE_ENABLED=true
OPENAI_API_KEY=...
JAANCH_AI_MODEL=gpt-6-sol
```

`.env.local` is gitignored. `OPENAI_API_KEY` is intentionally not a `VITE_` variable and therefore is not exposed through browser `import.meta.env`.

Important: this Vite middleware is the current development/preview host for the server endpoint. A production deployment must mount the same server contract in a real server/serverless runtime; a static-only host is insufficient for live AI.

### 4. Web AI Review surface

New:

```text
apps/web/src/AIReviewScreen.tsx
```

The main web navigation now exposes **AI Review**.

Current flow:
1. complete/run a deterministic Jaanch assessment;
2. save the check-in;
3. open **AI Review**;
4. explicitly consent to one external review;
5. Jaanch creates the minimized packet locally;
6. the UI shows counts for evidence facts, missing-evidence items, eligible labs and omitted raw-answer fields;
7. press **Run AI review**;
8. only validated output is rendered.

Consent is not persisted.

### 5. User-facing output

A valid review can show:
- concise overall explanation;
- preserved red flags;
- possible missing considerations;
- explicit disagreements with deterministic finding IDs;
- domain-level explanation;
- missing evidence;
- advisory next actions;
- treatment-advice gating reasons;
- provider/model/harness/schema trace.

Invalid structured output or a safety-invariant violation is hidden rather than partially rendered.

The UI repeatedly states that deterministic Jaanch remains authoritative.

## Privacy boundary

M10.1 does **not** mean no health data leaves the device.

When the user explicitly runs AI review, the minimized packet can still contain sensitive health evidence, findings, eligible lab values, safety context and missing-evidence state.

What is deliberately omitted:
- raw questionnaire answers as a raw answer map;
- stale/ineligible lab records;
- provider credentials;
- unrelated local history/check-ins;
- cloud-persistence credentials/identity tokens.

The OpenAI request continues to use `store: false` in the existing M10 provider baseline.

## Verification

### Non-live verification

`npm run verify` now includes the existing AI runtime checks plus `packages/ai-runtime/src/verifyWeb.ts`.

New checks verify:
- only the minimized packet is forwarded;
- the common strict output schema is preserved;
- provider/model traceability is returned;
- explicit consent is required at the server boundary;
- an arbitrary raw-answer request body is rejected.

Existing M10 checks continue to cover:
- packet minimization;
- stale-lab omission;
- urgent downgrade rejection;
- unsupported-domain self-care rejection;
- treatment advice gating;
- strict OpenAI JSON-schema request construction;
- `store:false`;
- harness/schema/version trace.

### Live five-mock gate

New command:

```bash
npm run ai:gate
```

It runs the configured live provider against all five existing mock profiles using the fixed 2026-10-09 fixture assessment date and prints:
- provider/model;
- validation status;
- highest priority;
- disagreement count;
- missing-consideration count;
- incremental-signal count;
- validation/provider errors;
- a JSON gate report.

A non-zero novelty count is **not** automatically considered better. A good AI reviewer should sometimes say that the deterministic assessment already covers the material issues. Manual usefulness review remains required.

## How to run locally

From repo root:

```bash
npm install
cp .env.example .env.local
```

On Windows PowerShell:

```powershell
Copy-Item .env.example .env.local
```

Edit `.env.local`:

```text
JAANCH_AI_LIVE_ENABLED=true
OPENAI_API_KEY=<your key>
JAANCH_AI_MODEL=gpt-6-sol
```

Then:

```bash
npm run verify
npm run web
```

In the browser:
1. run or import a profile;
2. save a check-in if needed;
3. open **AI Review**;
4. consent;
5. inspect the packet counts;
6. run the review.

For the repeatable five-profile live test:

```bash
npm run ai:gate
```

The CLI loads root `.env.local` when present; shell environment variables remain supported.

- AI conversation/chat history;
