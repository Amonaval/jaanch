# M13.4 — Narrow Clinical Interpretation Expansion

Status: **ENGINEERING IMPLEMENTED — OWNER CLINICAL/PROFILE RETEST REQUIRED**  
Effort: **High**

## Goal

Expand deterministic interpretation only where Jaanch already captures useful structured evidence and where a narrow, sourced, auditable rule can add clear consumer value without turning the product into a broad diagnosis engine.

M13.4 also adds a versioned local profile portability/test surface so realistic scenarios can be imported, exported and rerun quickly.

## Scope implemented

### 1. Blood pressure / cardiovascular context

Rule: `CV-BP-001`  
Source: `ESC-BP-2024`  
Applicability: adult, nonpregnant prototype.

Behavior:
- a recent user-confirmed `mmHg` reading is required;
- one reading is a measurement signal, not a hypertension diagnosis;
- 2024 ESC office-BP categories are used only as bounded screening context;
- marked readings trigger clinician-review language, never autonomous medication changes;
- known hypertension/BP-medicine context without a current reading creates an explicit evidence gap.

### 2. Lipid cardiovascular-risk context

Rule: `CV-LIPID-001`  
Source: `AHA-ACC-DYSLIPIDEMIA-2026`  
Applicability: adult, nonpregnant prototype.

Behavior:
- interprets confirmed recent total cholesterol / LDL / HDL / triglycerides in `mg/dL` only;
- does not silently convert units;
- LDL ≥160 mg/dL is treated as important risk context, not a universal treatment threshold;
- TG ≥500 mg/dL receives clinician-review context; TG ≥1000 mg/dL receives high-attention clinician-review context;
- measured values below those limited escalation thresholds are **not** labelled globally “normal” because lipid goals depend on overall cardiovascular risk and treatment context;
- Jaanch does not calculate PREVENT risk yet and does not autonomously start/stop/change lipid-lowering medicine.

### 3. Anaemia / iron-status evidence

Rule: `NUT-IRON-001`  
Sources: `WHO-ANAEMIA-2024`, `WHO-FERRITIN-2020`  
Applicability: nonpregnant adults age 18–65 in the current prototype.

Behavior:
- uses confirmed haemoglobin `g/dL` and ferritin `ng/mL`/numerically equivalent µg/L forms;
- uses WHO adult nonpregnant haemoglobin cutoffs (<12 g/dL female, <13 g/dL male) and severe <8 g/dL boundary;
- ferritin <15 ng/mL is treated as depleted-iron-store evidence in the narrow otherwise-healthy-adult context;
- low haemoglobin without ferritin and low ferritin without haemoglobin create explicit missing-evidence nodes;
- Jaanch does not infer the cause of anaemia and does not prescribe iron dose/duration autonomously.

### 4. Thyroid evidence

Rule: `MET-THYROID-001`  
Source: `NICE-THYROID-NG145`  
Applicability: adult nonpregnant prototype.

Behavior:
- interprets recent confirmed TSH only;
- thyroid history/medicine or a limited multi-symptom pattern can create a missing-TSH evidence gap;
- TSH ≥10 mIU/L or <0.1 mIU/L creates a clinician-review/confirmation signal;
- Jaanch explicitly does not diagnose hypothyroidism/hyperthyroidism from one TSH value;
- FT4/FT3 confirmation remains clinician-guided; thyroid medicine changes are not autonomous.

## Evidence integrity architecture

M13.4 does **not** simply promote every M13.3 recorded measurement into the old lab engine.

A separate `clinicalMeasurements.ts` boundary:
- validates marker, unit, collection date, verification, plausible range and freshness;
- chooses the latest eligible value per marker;
- materializes private `__m134_*` derived fields only inside the trusted capture path;
- tags trusted materialization with a module-private symbol;
- strips forged/internal fields from public `assess(...)` input;
- strips internal derived fields from persisted snapshots and profile export.

This preserves the rule:

> **captured evidence ≠ clinically eligible evidence.**

## M13.3 integration

Report confirmation still creates reviewed `RecordedMeasurement` objects for the broader markers. The updated report workflow then rematerializes the latest captured context before reassessment.

Therefore:
- extraction alone still changes nothing;
- explicit review is still required;
- unit/date/freshness/applicability gates still apply;
- eligible M13.4 markers can now influence the bounded new rules;
- Vitamin D, fasting/random glucose and unknown markers remain recorded/unassessed in M13.4.

## Profile portability / mock testing

Protocol: `JAANCH-PROFILE-1.0`

Implemented:
- versioned JSON import/export;
- imported profiles are rerun through the **current** deterministic engine rather than trusting stored conclusions;
- export preserves a runnable draft and optional local history;
- internal M13.4 derived evidence fields are removed on import/export;
- web downloads JSON files;
- mobile imports JSON documents and exports via the native share sheet;
- profile portability remains local prototype infrastructure, **not** M13.5 account/cloud persistence.

Built-in + repo fixtures:
1. low-risk adult;
2. cardiometabolic + lipids;
3. vegetarian + low B12 + iron/anaemia evidence;
4. thyroid signal;
5. severe triglyceride signal while on lipid-lowering medicine.

Repo fixtures: `examples/mock-profiles/`.

## Explicit non-goals

- no broad disease catalogue;
- no Vitamin D interpretation in this mission;
- no direct fasting/random glucose interpretation expansion;
- no PREVENT/ASCVD risk calculator;
- no medication-dose decision engine;
- no diagnosis from one measurement;
- no pregnancy-specific BP/lipid/thyroid rules;
- no cloud identity, encrypted profile store, backup or cross-device sync — those remain M13.5/release work.
